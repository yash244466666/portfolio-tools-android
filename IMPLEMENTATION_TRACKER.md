### 2026-09-15 — Hosted CI exhausted its allowance: moved to a self-hosted runner (ADR 0024)

- **Symptom.** Every job stopped being allocated a runner: each failed ~2 s after starting with **zero steps executed** and `runner_id: 0`, and no log blob existed at all (`BlobNotFound`). It presented as a change-specific breakage because the first failing run was on a feature branch.
- **Cause, established rather than guessed.** Re-running `main`'s **own previously-green commit** failed identically, so no feature change was involved. GitHub's status page was operational and the repository's Actions permissions were normal. Measured usage: ~201 runs since 2026-09-05, ≈**2,400 billed job-minutes** against the **2,000-minute monthly allowance** for a private repository on the Free plan. A secondary cause was visible in the same data — the workflow ran the full two-job suite on every push to every pull-request branch with no `concurrency` cancellation, so a branch pushed three times paid three times.
- **Decision (ADR 0024).** Both jobs now run on a self-hosted runner registered from the maintainer's workstation (label `yash-linux`), as a user systemd service with `Linger=yes`, so it survives logout and reboot. Making the repository public would have fixed the cause exactly and is prohibited; a self-hosted runner removes the metered dependency instead.
- **Burn reduction, kept regardless of runner choice.** `concurrency` cancels a superseded pull-request run (`main` is never cancelled); `paths-ignore` skips prose-only pull requests; and **`pnpm format:check` was added** — a declared repository gate that CI had never enforced, which is why formatting drift accumulated silently across merged batches.
- **Two self-hosted defects found and fixed while bringing the runner up.** (1) `setup-java`'s `cache: gradle` post step spent many minutes compressing and uploading a **7.5 GB** `~/.gradle` to GitHub's cache service — the job sat in "Post Run actions/setup-java" with a Java process at ~90 % CPU and did not yield to cancellation. On a self-hosted runner the pnpm store and `~/.gradle` already persist on disk, so all three `cache:` inputs were removed. (2) The Playwright install dropped `--with-deps`, which exists only because hosted images lack the browsers' system packages and would otherwise need interactive `sudo` for apt.
- **Measured resource profile** (from the runner cgroup, for future host sizing): **`android-debug` peaks at ~5.1 GB**, and the `web-quality` job reached ~2.2 GB mid-run. Both jobs exceed what the maintainer's existing VPS instances can host — they are 2 vCPU / **954 MB RAM** (≈440 MB available) and already run production services (mail, file sync, object storage, MariaDB, POS) — so a self-hosted runner was deliberately **not** installed there.
- **Verification.** Both jobs pass on the self-hosted runner against the same commit: `android-debug` 3m30s, `web-quality` 4m08s, **7m44s end to end**, `runner_name=yash-portfolio-ci` — where the same class of commit had failed with `runner_id: 0` and no runner at all. The suite runs `pnpm format:check` for the first time in this repository's CI history. Removing the Actions caches also cut the runner's memory peak from **5.1 GB to 3.3 GB**. ADR 0024 is at `docs/decisions/0024-self-hosted-ci-runner.md` and `CLAUDE.md`/`AGENT.md` section 24 records the topology.
