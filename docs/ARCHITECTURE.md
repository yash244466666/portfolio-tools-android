# Foundation Architecture

> Status: accepted for the foundation; the 87-tool first-release scope is accepted, while identity and other irreversible release decisions remain provisional.

## Runtime shape

```text
React screen/tool
      |
      v
Pure feature logic + typed tool metadata
      |
      v
Platform service contracts
      |
      +-------------------+
      |                   |
      v                   v
Web development       Capacitor Android
adapters              adapters/plugins
      |                   |
      +---------+---------+
                v
        Bundled Vite application
                v
          Signed Android artifact
```

Dependency direction is one way. Tool features may depend on shared UI and platform contracts. They may not depend on Capacitor plugins, Android classes, the portfolio repository, or generated Android asset output.

## Main boundaries

### Application shell

`src/app/` owns route parsing, top-level navigation, catalog discovery, global theme, favorite/recent IDs, and settings. Internal routes are hash-based so bundled local navigation does not require server fallback.

### Tool registry

`src/tools/registry.ts` is a deterministic compile-time registry. Implemented components are lazy imports. A tool cannot be enabled without an implementation. The registry also exposes risk, persistence, and network classifications needed by UI and tests.

The audited public version 1 scope contains 86 of the 87 upstream catalog tools (ADR 0021 excludes youtube-downloader) plus 14 new original tools for a total of 100 tools (ADR 0022). The 12-tool architecture milestone proved the reusable paths, and batches 2 through 16 have expanded the registry to all 100 enabled entries. Production submission additionally requires every entry to pass the remaining device-evidence, certification, and release gates.

### Tool features

Each tool directory owns its UI, pure logic, fixtures, and tests. Algorithms should be usable without React. Platform effects enter only through interfaces.

Tools that execute hostile user input use the terminable-Worker pattern proven by Regex Tester: a pure bounded engine runs inside a lazily created classic Web Worker, and the UI thread enforces a wall-clock deadline that terminates and replaces the Worker when a run wedges (ADR 0010). There is deliberately no main-thread fallback for such execution.

### Platform layer

`src/platform/contracts.ts` defines stable capability contracts. `src/platform/services.ts` selects web or Capacitor implementations once. Adapter failures use stable safe error codes.

Android document selection and Save As use the app-owned, versioned `DocumentFiles` bridge. It returns validated `content://` metadata from `ACTION_OPEN_DOCUMENT` and streams bounded generated output from a private cache handoff into an `ACTION_CREATE_DOCUMENT` destination. The bridge accepts no arbitrary paths or intents and requires no storage/media permission. File-consuming tools read picked content through the versioned bridge's `digestContent` (native streaming hash, 1 GiB cap) and `readContent` (bounded 16 MiB copy) operations, restricted to URIs the picker returned in this process.

Android clipboard writes use the app-owned, versioned `SensitiveClipboard` bridge so secret-classified copies can carry Android 13+ sensitive-clipboard metadata; older versions degrade to a normal write. It validates and bounds every write, never reads the clipboard or logs values, and requires no permission. Clipboard reads and the stale-timer-protected timed clear remain on the official plugin and adapter.

Generated-file cache (`cache/share/` and `cache/save/<operation>/`) is cleaned by the app-owned, versioned `GeneratedCache` janitor using a pure policy: bounded deterministic retention windows, ownership-validated deletion targets, active-operation protection, low-space behavior, and canonical-path containment. It runs at bridge load and opportunistically before generated-file operations, and never touches other cache or user data.

### Persistence

Preferences are namespaced and JSON encoded. This is suitable for settings, bounded IDs, the versioned Notes payload, and the versioned Pomodoro reconstruction state, not arbitrary large documents. Each new durable tool requires its own schema, migration, size, export, deletion, and recovery design before implementation.

### Android host

The Android project is tracked because manifests, permissions, backup rules, network policy, resources, R8, Activity behavior, and native plugins are product code. Web assets under the Android project are generated by Capacitor sync and are not edited directly.

WebView renderer termination is recovered natively through a Capacitor bridge listener: at most one rate-limited automatic Activity recreation per process window, then a native theme-aware safe-mode screen with a manual reload action. The crashed WebView is never touched and recovery never depends on JavaScript still running.

The Android instrumentation source set drives the built-in `https://app.yash.tools` WebView without a development server. ActivityScenario covers Activity recreation, Espresso Intents stubs and inspects scoped document/share requests, and stable UI Automator APIs cover system Back and notification-permission UI. A test-APK-only synthetic content provider supplies bounded PNG fixtures; it is absent from production manifests and cannot expand the shipped permission/export budget. A host-side script force-stops the exact debug package between two instrumentation phases to prove true new-process reconstruction rather than same-process Activity recreation.

Android view-hierarchy and legacy form persistence are disabled for the WebView, and its subtree is excluded from Autofill and Content Capture on supported versions: transient tool inputs must not acquire an undeclared persistence path, while explicitly reviewed durable values reconstruct through `PreferenceStore`. The Activity owns the narrow system-Back policy for hash routing: a nested bundled route returns to the catalog and the root route delegates to Capacitor/Android (ADR 0019). Tools remain Android-agnostic.

## Security model

- Only bundled application HTML receives native bridge access.
- External HTTPS pages open outside the app WebView.
- Cleartext networking is disabled.
- Android backup/device transfer is excluded for app-private data.
- FileProvider exposes only the cache `share/` subtree.
- Release build is minified and resource-shrunk.
- Network providers are explicit and narrowly allowlisted.
- Sensitive user content is excluded from logs and automatic persistence.

## Expansion rule

If a new tool needs a new global pattern, pause and prove the pattern through a representative implementation, adapter contract, tests, permissions/data review, and ADR before applying it to the catalog.
